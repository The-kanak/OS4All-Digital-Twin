# Synthea Synthetic FHIR Integration Guide

## 1. Executive Summary

As part of the **Happiest Health Digital Twin Challenge 2026**, OS4All Digital Twin ingests standard synthetic healthcare data formatted in **HL7 FHIR (Fast Healthcare Interoperability Resources)** generated by the open-source [Synthea™ Patient Generator](https://github.com/synthetichealth/synthea).

This integration fulfills the challenge requirement for a realistic, longitudinal **Static / Historical EHR** foundation while maintaining an architectural separation between:
1. **Static / Historical EHR Data** (ingested from FHIR: demographics, SNOMED conditions, LOINC laboratory panels, historical encounters, RxNorm medications).
2. **Dynamic / Real-Time Telemetry Data** (ingested from IoT/CGM streams: heart rate, HRV, SpO2, sleep staging, steps, 5-minute continuous glucose telemetry).

---

## 2. External Dataset Location & Safety Boundary

* **Synthea FHIR Directory**: `D:\Projects\synthea-master\output\fhir`
* **File Volume**: 15 synthetic patient JSON bundles (~40 MB total).
* **Isolation Rule**: 
  * `synthea-master` is treated as a **read-only external synthetic data source**.
  * No files inside `D:\Projects\synthea-master` or the original `D:\Projects\OS4All` directory are modified, moved, or deleted.
  * No 40 MB raw directory copying into the repository; data is ingested on-demand via the backend FHIR ingestion layer.

## 6. Configuration & API Endpoints

### 6.1 Configuration (`application.yml`)
```yaml
app:
  synthea:
    fhir-path: ${SYNTHEA_FHIR_PATH:D:/Projects/synthea-master/output/fhir}
```

### 6.2 Available REST APIs

| HTTP Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/ehr/synthea/candidates` | Scans the configured FHIR directory and lists candidate patients with their metabolic profiles. |
| `POST` | `/api/ehr/import/synthea` | Ingests selected or metabolic candidates into the Static EHR database and connects them to Digital Twins. Optional query parameter `?limit=5`. |
| `GET` | `/api/ehr/patients` | Returns all patients currently in the Static EHR repository, including imported Synthea profiles. |
| `GET` | `/api/ehr/patients/{id}/conditions` | Returns SNOMED-coded conditions for a specific patient. |
| `GET` | `/api/ehr/patients/{id}/labs` | Returns LOINC-coded historical laboratory observations. |
| `GET` | `/api/ehr/patients/{id}/medications`| Returns historical and active medication requests. |
| `GET` | `/api/ehr/patients/{id}/history` | Returns complete longitudinal medical encounters and clinical history. |

## 7. Security & Sanitization

1. **Path Traversal Protection**: The backend enforces `resolveSafePath()` which verifies that any user-specified path stays within the authorized directory boundary and strips any `..` path manipulation attempts.
2. **Deterministic ID Generation**: Ingested patient IDs use standard RFC-4122 version 3 UUIDs generated from the Synthea FHIR identifier (`UUID.nameUUIDFromBytes(("synthea-patient-" + fhirId).getBytes())`), preventing collisions and ensuring idempotency upon repeated ingestion.
3. **Data Anonymization**: Synthea generates entirely fictitious names, addresses, and clinical dates. No real Protected Health Information (PHI) is present.
